# cm_custom_flow (Resource)

Creates, updates and destroys custom flows. For more information: [ControlMonkey Documentation](https://docs.controlmonkey.io/main-concepts/runs/custom-flows)

## Example Usage

### Custom flow with an inline flow definition
```terraform
resource "cm_custom_flow" "opa_validation" {
  name       = "OPA validation"
  is_enabled = true

  flow_yaml = <<-EOT
    version: 1
    customFlows:
      run:
        steps:
          terraformPlan:
            after:
              - name: evaluate OPA policy
                cmd: |
                  opa eval --data policy.rego --input showPlanOutput.json "data.terraform.deny"
                failureBehavior: stop
  EOT
}
```

### Custom flow whose definition is loaded from a file
```terraform
# Keep the flow definition in your repository and load it from a file
resource "cm_custom_flow" "from_file" {
  name       = "Custom flow from file"
  is_enabled = true
  flow_yaml  = file("${path.module}/cm.yaml")
}
```

## Schema

### Required

- `flow_yaml` (String) The YAML definition of the custom flow. Learn more about the supported structure [here](https://docs.controlmonkey.io/main-concepts/runs/custom-flows).
- `is_enabled` (Boolean) Whether the custom flow is enabled. When disabled, the custom flow will not run for any of its mapped targets, but the mappings are retained.
- `name` (String) The name of the custom flow.

### Read-Only

- `id` (String) The unique ID of the custom flow.

`cm_custom_flow` can be imported using the ID of the Custom Flow, e.g.
